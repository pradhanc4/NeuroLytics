2. Important Project Principles

These are already established and should remain consistent throughout development.

Data principles
SQL is the source of truth.
Historical data is stored in SQL.
CSV/input files are ingestion sources, not the permanent source of truth.
Leading zeros must be preserved.
0 is a valid actual value.
NULL means missing/unknown.
0 must never automatically become NULL.
NULL must never automatically become 0.
Missing calendar dates are different from records containing zero.
Duplicate historical records must be detected.
Dates must remain actual dates.
No future information should leak into training.
ML principles
Leakage-safe features
Time-aware datasets
Walk-forward validation
Historical backtesting
Model comparison
Calibration
Explainability
Model/version tracking
Monitoring
Drift detection
Important project boundary

The system is being built as a technical analytics/ML platform. Statistical/model outputs should be treated as model-generated analysis rather than guaranteed future outcomes.

becomes:

12345678

The original Open/Jodi/Close values are also retained.
