## 3. Formal Comparison Contract

SequenceModelComparisonResult records:
- model kind
- model version
- observation count
- log loss
- accuracy
- Top-K accuracy
- Brier score
- expected calibration error
- deterministic comparison score
- optional log-loss baseline delta
- optional accuracy baseline delta

The comparison score is:

accuracy / log_loss

with a numerical floor on log loss.

This is a comparison signal, not a replacement for the individual evaluation metrics.

## 4. Evaluation Alignment Contract

An ensemble is valid only when all component evaluations share:
- dataset identity
- observation count
- target sequence
- probability-row count

This prevents accidental blending of predictions produced on different sample universes.

The implementation deliberately rejects mismatched evaluation windows rather than silently truncating or fabricating alignment.

## 5. Ensemble Weighting Methods

Three deterministic methods are supported:

### 5.1 Equal Weight

Each model receives identical weight.

### 5.2 Inverse Log Loss

Each model receives weight proportional to:

1 / log_loss

Lower log loss therefore contributes more weight.

A numerical floor prevents division by zero.

### 5.3 Softmax Score

Weights are derived from a bounded exponential transform of:

accuracy / log_loss

The calculation is deterministic and normalized.

## 6. Probability Blending

For each observation and each digit 0–9:

ensemble_probability[digit]
=
sum(model_weight × model_probability[digit])

The blended row is normalized again to guarantee a valid ten-class probability distribution.

Digit 0 remains a first-class valid probability class.

## 7. Ensemble Evaluation

Every generated ensemble is evaluated using the Phase 34 metric contracts:

- log loss
- accuracy
- Top-K accuracy
- Brier score
- expected calibration error

The ensemble also preserves:
- targets
- observation count
- dataset identity
- model kinds
- model weights
- deterministic ensemble identity

## 8. Ensemble Selection

The deterministic selection order is:

1. lower log loss
2. higher accuracy
3. higher Top-K accuracy
4. lower Brier score
5. method name as deterministic final tie-breaker

This selection is reproducible for identical inputs.

## 9. Ensemble Report

SequenceEnsembleReport contains:
- version
- dataset identity
- formal model comparison report
- all generated ensemble results
- selected method
- selected ensemble identity
- deterministic report identity

Three standard ensemble methods are generated by default.

## 15. Leakage Boundary

Phase 35 is downstream-only.

It does not:
- query SQL
- access future historical records
- alter point-in-time features
- create target dates
- change sequence windows
- retrain models
- manufacture missing observations

It consumes Phase 34 evaluation outputs.

For production use, evaluation/calibration inputs must already represent a valid chronological evaluation/calibration split.
