# NeuroLytics — Phase 63 Retraining Dataset Pipeline

## Status

Phase 63 — Retraining Dataset Pipeline is COMPLETE LOCALLY.

Version: 63.0.0

## Purpose

Phase 63 converts an approved Phase 62 RETRAIN decision plus leakage-safe FeatureArtifact history and aligned historical targets into a deterministic retraining dataset report.

The phase prepares data only. It does not train models, select models, promote versions, mutate production state, or deploy artifacts.

## Source Contracts

Required sources:

- valid Phase 62 RetrainingDecisionReport
- decision must be RETRAIN
- FeatureArtifact history
- historical target mapping keyed by target date
- explicit data_identity

Every FeatureArtifact must be validation status VALID and leakage status CLEAN.

All artifacts must share:

- one feature version
- one feature-name sequence
- unique target dates

Artifacts are sorted chronologically before dataset construction.

## Target Contract

Every feature-artifact target date must have an aligned target value.

Targets may be numeric or string scalar values. Boolean targets and non-finite numeric targets are rejected.

No target value is inferred or fabricated.

## Dataset Split Contract

The default chronological split is:

- TRAIN: 70%
- VALIDATION: 15%
- TEST: 15%

At least one row is required in every split.

The split is chronological, so later observations cannot enter an earlier training partition.

## Dataset Row Contract

Each row preserves:

- target date
- feature values in declared feature order
- target
- split
- deterministic source FeatureArtifact identity

No future feature values are generated by Phase 63.

The pipeline consumes already leakage-clean FeatureArtifacts.

## Lineage

The report preserves:

- model identity
- Phase 62 decision report identity
- source data identity
- feature version
- feature names
- per-row feature-artifact identity
- dataset configuration

The final report identity is a deterministic SHA-256 identity over the dataset inputs and resulting dataset structure.

Identical inputs produce the same dataset identity. Changing the dataset ID, target values, configuration, or source lineage changes the identity.

## Validation

Strict validation checks:

- report type and version
- dataset/model/decision/data identities
- feature version and feature names
- row structure
- target validity
- split validity
- duplicate dates
- split-date reconciliation
- excluded-date overlap
- configuration validity
- deterministic report identity prefix

## Safety Boundary

Phase 63 does not:

- train a model
- tune hyperparameters
- select a champion
- promote a model version
- mutate lifecycle state
- deploy artifacts
- change production traffic
- generate predictions
- modify historical SQL data
- modify FeatureArtifacts

Actual automated retraining remains Phase 64.
